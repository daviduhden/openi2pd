# Language policy

openi2pd ships four user-interface languages. English is the source catalog and
the fallback; a missing translation never blocks the UI and never falls back to
a different translated language.

| Surface | Tags | Notes |
|---|---|---|
| Native TUI, tools and daemon messages | `en`, `es`, `ru`, `zh-Hans` | `--lang`, the `lang`/`tui.language` configuration keys, or `LC_ALL`/`LC_MESSAGES`/`LANG` |
| Android application | `en`, `es`, `ru`, `zh-CN` | `values`, `values-es`, `values-ru`, `values-zh-rCN`; `zh-CN` is the Android resource tag for Simplified Chinese and maps to the same `zh-Hans` catalog intent |
| Documentation | English | Technical documentation is maintained in English; translations are a separate, approved effort |
| Store metadata | English (`en-US`) | Additional Fastlane locales may be added only with reviewed translations |

## Selection and fallback

- Native: `--lang` overrides the `lang`/`tui.language` configuration, which
  overrides the process locale. An empty selection consults `LC_ALL`, then
  `LC_MESSAGES`, then `LANG`. Unknown tags and `C`/`POSIX` fall back to English.
  POSIX codesets such as `es.UTF-8` and `ru_RU.UTF-8` do not change the catalog.
  Chinese script subtags match exactly: explicit `zh-Hans-*` selects Simplified
  even with a different region; `zh-Hant-*` uses English. Without a script,
  bare `zh`, `zh-CN` and `zh-SG` select Simplified, while `zh-TW`, `zh-HK` and
  `zh-MO` use English. Invalid script prefixes never select Simplified.
- Android: the per-app language setting (`AppCompatDelegate.setApplicationLocales`)
  selects a catalog without changing the device locale. The system language is
  the empty selection. `zh-TW`, `zh-Hant` and `zh-HK` fall back to **English**;
  Traditional Chinese is not shipped and Simplified text is never presented as
  Traditional.
- `LC_NUMERIC` is pinned to `C` once during initial native selection so sizes
  and rates do not change their decimal separator. Terminal startup changes
  only `LC_CTYPE`. Concurrent translation readers retain one immutable locale
  selection; switching language cannot invalidate an in-flight plural lookup.

## Plural rules

| Language | Native forms | Android forms |
|---|---|---|
| English | one, other | `one`, `other` |
| Spanish | one, other | `one`, `other` |
| Russian | one, few, many | `one`, `few`, `many`, `other` |
| Simplified Chinese | one form | `other` only |

Native plurals are keyed by the English plural text (`ntr`) and stored in
`i18n/*.cpp`. Android counts use `<plurals>` and `getQuantityString`; a
translated sentence never concatenates a number with an English plural.
Native integer categories ignore sign, including the minimum signed integer.

## What is translated

User-visible labels, status text, prompts, validation messages, notifications,
tunnel/torrent panels and TUI help prose use resources. Native catalogs retain
the ordered printf operand types, lengths and dynamic width/precision; Android
uses positional placeholders. Native positional printf syntax and `%n` are
rejected. Composition separators are preserved after multibyte text too.

Native English keys are the source catalog and identity fallback, with matching
Spanish, Russian and Simplified Chinese tables. The current checker covers 628
keys and 14 plural groups. It harvests compact tabs, help, option descriptions
and terminal errors as well as direct translation calls. Rendered rows and
user/peer text never become guessed translation keys. Closed mappings localize
known torrent/router states and engine errors without rewriting snapshots;
unknown diagnostic bodies remain unchanged rather than translating user data.

The Android continuation adds 34 resource keys per locale for these presentation
categories, file progress and percentages. Services and Quick Settings resolve
per-app resource contexts through AndroidX, including API 29-32; notification
refresh also observes locale changes. This still requires device validation.

Never translate protocol verbs, IPC commands, configuration keys, log levels
and tokens, field names, torrent/LeaseSet status wire values, peer flags,
transport names (`NTCP2`, `SSU2`, `SAM`, `I2CP`, `I2PSnark`), hashes, URLs,
magnet links or persisted formats. Those identifiers are interoperability
contracts.

## Adding or changing a language

1. Add the key to all four native catalogs or all four Android locales in the
   same change; the checkers reject partial catalogs.
2. Keep printf conversions and the declared plural arity.
3. Never copy English text into a translated value as a placeholder unless the
   term is an intentional protocol name.
4. Run only compile-free checks locally: `i18n-static`,
   `check-android-locales.pl` and `perl i18n/check-i18n-catalogs.pl`.
   `test-i18n-locale`, `test-i18n-format`, `test-tui-terminal`, the maintenance
   checker fixtures, JVM tests and `LocaleResourceTest` execute only in manual
   CI. Native tests carry the `i18n`/`unicode` labels; the existing full native
   and sanitizer suites include them. Android device coverage uses the manual
   `android_ui` option and must be enabled to validate locale recreation,
   notification/tile refresh, TalkBack and tablet layout.
5. Record UI-catalog changes in `TODO.md`/`PROGRESS.md`; documentation
   translation needs a separate approval and is not implied by UI coverage.

The canonical color/identity rules are in
[visual identity](branding/README.md); the catalog files are
`i18n/{English,Spanish,Russian,ChineseSimplified}.cpp` and
`android/app/src/main/res/values*`.

Terminal width and deletion operate on Unicode scalars, not grapheme clusters.
Combining marks survive clipping at a fitting base's last column; backspace
removes a whole scalar. Prefilled prompts never split UTF-8 and incomplete or
invalid input is rejected before IPC. Emoji grapheme/ZWJ rendering still
depends on the terminal; no cross-terminal pixel/layout equivalence is claimed.
