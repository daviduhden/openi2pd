# Interoperability fixture matrix

Pinned reference: I2P Java `i2p-2.13.0`, commit
`9134f808337b401e8e53c73734c81fab04280c9d`, at
`$I2P_JAVA_REFERENCE` (read-only, outside this repository).

This matrix lists every fixture needed to make the differential harness
reproducible. It separates what is **checked in** from what the user must
**capture** with the reference build. No Java output in this directory was
invented: every checked-in byte vector is reconstructed from a documented
layout and carries line references to the pinned Java source; the validator
re-checks those references.

Status vocabulary:

| Status | Meaning |
|---|---|
| **Checked in** | Deterministic input + expected parse committed under `vectors/`. Validated statically by `check-vectors.pl`; differential execution still requires `--binary`. |
| **Template** | Deterministic constants/rules committed under `templates/`, but no wire bytes (the bytes contain keys/signatures/time). |
| **Capture** | Must be produced by the user from the reference build or a controlled loopback run, then normalized to hex/JSON with provenance. Never invent these values. |
| **Dynamic** | End-to-end scenario, not a file. Recorded in a run log, not in this repository. |

**No dynamic test has been executed.** The only executed checks are the static
fixture-integrity checks described in `README.md`.

## 3. Tunnel build records and time windows

Layouts (clear text, inside the encrypted record):

| Record | Size | Time field | Source |
|---|---|---|---|
| ElGamal `BuildRequestRecord` | 528 | hours since epoch, rounded down | `BuildRequestRecord.java:312-323`; `I2NPProtocol.h` |
| ECIES `BuildRequestRecord` | 528 | minutes since epoch, rounded down | same |
| Short ECIES record | 218 | minutes since epoch, rounded down | `I2NPProtocol.h`; `TunnelConfig.cpp` |

Acceptance rule in Java (`BuildHandler.java:101-104,774-792`):

- ECIES: `timeDiff = floor(now/minute) - requestTime`; reject if
  `timeDiff > 8 min` or `timeDiff < -5 min`.
- ElGamal: `timeDiff = floor(now/hour) - requestTime`; reject if
  `timeDiff > 65 min` or `timeDiff < -5 min`.
- Because both sides round down, an 8-minute ECIES request is accepted and a
  9-minute one is rejected. ElGamal request times are whole hours, so the
  previous hour (`timeDiff = 60`) is accepted, two hours (`120`) is rejected,
  the same hour (`0`) is accepted, and a future hour (`-60`) is rejected.

`templates/tunnel-build-time-windows.json` records these boundary cases. The
actual encrypted records must be captured because they contain ephemeral keys
and signatures.

## 10. Capture and normalization rules

1. Build the Java reference outside this repository; never vendor it.
2. Generate keys in a throwaway directory outside the checkout; never commit
   private keys, session keys, ratchet tags or router identities.
3. Normalize captures to the documented JSON schema. For byte fixtures use
   lowercase hex with 64 hex characters per line and a `#` provenance header;
   for text protocols use the exact bytes (including `\n`).
4. Every `.case.json` must contain `provenance.spec`, `provenance.java` and
   `sha256`. The validator checks the file hash and, when a reference is
   supplied, the cited Java file/line/substring.
5. Keep valid and malformed inputs in separate directories. Cap each corpus
   (for example 64 cases per area) and reject inputs larger than the protocol
   maximum before parsing.
6. A capture is evidence, not a specification. If Java and the specification
   disagree, record both and do not silently accept the Java behavior.
